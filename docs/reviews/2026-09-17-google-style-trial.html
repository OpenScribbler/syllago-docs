Interpretation

204 spaced-em-dash findings reflect a house-style conflict, not 204 broken passages. Parenthetical and passive-voice rules intentionally over-select text for editorial review. Syllago needs overrides and vocabulary before this can drive fixes.

The semantic layer

Jev receives one narrow Choice question per applicable unit and returns violation, compliant, or not_applicable with probabilities.

Two harness bugs caught

Both early “style findings” were caused by segmentation, not writing. The model was judging the input it received correctly.

Merged list items

Three numbered items were initially treated as one paragraph, so Jev flagged it for containing multiple ideas. List items are now independent units.

Code comment as heading

# Arch inside a shell block was initially treated as a document heading. Heading extraction now honors fenced code, comments, and frontmatter.

Path to an editing queue

Normalize

Parse MDX into headings, paragraphs, list items, links, and procedures while excluding generated content and code.

Evaluate

Run Vale for exact rules and Jev only for the semantic rules relevant to each unit.

Prioritize

Group by page, remove project exceptions, and order high-confidence violations ahead of review candidates.

Edit and verify

Give an LLM one page and its rule-linked queue, request minimal diffs, then rerun every applicable check.

Recommended next experiment

  1. Label compliant, violating, and near-miss passages for each of the five Jev rules.
  2. Measure precision and recall per rule; do not use one global threshold without evidence.
  3. Decide which Google Vale preferences Syllago adopts, overrides, or disables.
  4. Generate one combined JSON and Markdown report grouped by page.
  5. Only then ask an editing LLM to propose small, rule-scoped patches.
